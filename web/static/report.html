How the bots play, and what each part is worth

A statistical account of the Schieber bots: what happens during a round and during a single move, when each part was built, and the measurement behind every default. Every figure on this page is read from docs/measurements.json. None of them are typed into the page, so re-measuring updates the page. It covers Schieber. Sidi Barrani, the second game mode, is measured in points a hand and is recorded in docs/measurements.md §5v.

1. What happens when

A game is a series of rounds. In each round the engine deals the cards, the dealer's seat picks trump, and nine tricks are played. The Python engine is the authority on the rules. It decides what each seat may see and re-checks every move a bot sends back.

A round

  1. DealSplitMix64 → Fisher–Yates from one game seed, identical in Python and Rust, so any game replays exactly.deal.py · deal.rs
  2. TrumpA rule-based score for each of the six contracts, or "schieben" (pass trump choice to the partner). Weights tuned by simulation.trump_weights.json
  3. Weis & StöckEach seat announces its Weis in the first trick, and the best one is shown. These are exact facts: bots rule out every imagined deal that contradicts them.weis.py · announce.rs
  4. 9 tricks36 moves in total. Each bot move goes through the pipeline below.game.py
  5. ScorePoints × the contract multiplier. The game runs to the target score.scoring.py

One bot move (~2 s natively)

  1. ObservationOwn hand, public history, legal moves, decision_seed. Nothing else, and a fuzz test enforces it.observation.py
  2. Hard constraintsVoids proven by play, shown Weis cards, called Weis values. Worlds that contradict them are dropped, not down-weighted.voids.py · belief.rs
  3. Pool of worlds4,096 deals of the hidden cards consistent with everything proven.determinize.rs
  4. WeightsEach world weighted by how likely the other seats' plays and bid were under it, using a small learned play model.play_policy.json
  5. ISMCTSA single search tree shared across all imagined deals: 40 × 3,840 = 153,600 iterations. Inside the tree the other seats move by the play model.ismcts.rs
  6. ConventionsA Swiss convention (a card the partner expects) may replace the search's pick if it scores within 0.01 of the best.convention.py
  7. ValidateThe server re-checks the move. If a bot times out, a random legal card is played instead.legal.py

    3. Protocol and statistics

    The unit

    The unit is the share of a round's points one agent's team takes, averaged over deals. 50% means the two agents are equal, and +1.0 is one percentage point of the round's points. Whole-game figures count games won instead. They are about 20 times noisier per sample.

    Double rounds, common random numbers

    Each deal is played twice with the teams swapped, both times from the same game seed. So the cards and the random numbers are the same for both sides, and only the agents differ. An agent playing itself scores exactly 50% on every deal, and a test checks this.

    The test

    di = si − 0.5
t = mean(d) / (sd(d) / √n)
p = 2 · (1 − Φ(|t|))

    This is a paired test on per-deal differences. ± sd in a table is the per-deal standard deviation, not a standard error. The error bars on this page are 95% confidence intervals, 1.96 · sd / √n.

    Rules adopted after six borderline results died

    1. Predict the direction and the mechanism before measuring.
    2. Replicate on a fresh seed before anything becomes a default.
    3. If a change makes a move more expensive, it must win at equal wall-clock time to ship.

    Power: the smallest effect a run can see

    Minimum detectable effect at α = 0.05 with 80% power, ≈ 2.8 · sd / √n, in points of a round's share. This is why effects of a few tenths of a point needed 3,000–6,000 deals.

    5. The search

    Budget: the shared tree keeps paying

    Each budget plays against the same algorithm at 2,400 iterations. The old voting search (a separate tree per imagined deal, then a vote) stopped improving near 2,400. The shared tree keeps improving up to 64 × 2,400 and is flat after that. The bots serve 153,600.

    Splitting a fixed budget

    2,400 iterations split between imagined deals and iterations per deal, against 40 × 60. The curve is an inverted U with a broad flat top. Too few worlds is as bad as too little search per world.

    Resampling: a cliff, not a slope

    How many iterations share one imagined world before the next is drawn. The gain from ISMCTS is intact at 4 and gone at 8. Shipped: 4.

    The exact endgame solver: less is better

    Handing the last k cards to a perfect-information solver, against k = 5. A perfect solve inside a world that is mostly wrong adds strategy fusion (the search acts as if it knew the hidden cards). Switching the solver off was the largest single gain in the record.

    6. Beliefs: the largest lever

    With probability p the search is handed the true deal instead of an imagined one. The curve prices information about the hidden cards: a fifth of an oracle buys a third of the cheater's advantage. Reading the other seats' plays and bid put the shipped bot at about 12% of an oracle, and it landed on the curve in real play. Sharper settings, a larger pool, a belief network and a retrained play model each scored higher offline and measured null in play.

    7. Trump selection

    The selector is linear in its weights. arena/contracts.py priced every contract on 3,000 hands × 16 deals, and arena/fit_trump.py searched the weights on half of the hands and reported the gain on the other half. The result was written to trump_weights.json, which Python and Rust both read.

    8. Networks on a CPU: closed

    A value network at the leaves

    Error of each way to judge a leaf position, measured against how the round actually ended (RMSE, lower is better). The network beats the single random playout a leaf gets, but not the average of the thousands of playouts the search builds, and it is null in play.

    A policy network instead of the search

    Distilled from 311,756 of the search's decisions and played with no search at all. Share of points against each opponent.

    10. The trained files, and when they change

    Everything learned lives in krass_jass/data/ as JSON and is committed. Rust compiles it in with include_str!, so the browser build needs no file system. Nothing regenerates these files during play, a build or a deploy. Each one changes only when its training script is run by hand and the result is committed.
